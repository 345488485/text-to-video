# 一句话 AI 视频 Agent 平台——需求分析与工程实施蓝图

> 文档状态：Draft v1.0  
> 更新日期：2026-08-27  
> 目标读者：产品、设计、前后端、算法/Agent、测试、运维、安全、法务、运营与商业负责人  
> 项目定位：面向个人创作者、营销团队与企业客户的商用 AI 视频生成 SaaS

## 当前开发进度

仓库已经包含一个可运行的 MVP 纵切面：

- 响应式 AI 视频创作工作台。
- 曜石黑、云境白、东方绛三套可切换主题。
- 一句话提示、智能润色、画幅/时长/质量选择和额度预估。
- 创建、查询、取消任务的异步 API，以及与真实接口隔离的幂等 Mock 测试供应商。
- SQLite 持久化账户、任务、额度预留/结算/释放、套餐、账单流水和真实作品库。
- 任务进度、真实视频预览与下载；只有成功任务会进入最近创作。
- 火山方舟 Seedance 2.0 创建、查询、取消任务的真实适配器。
- Python 自动化测试和真实浏览器桌面/移动端验收。

使用 `uv` 创建环境并启动：

```bash
uv sync
uv run python run.py
```

打开 `http://127.0.0.1:4173`。只需填写 API Key 的配置步骤见 [`docs/API_CONFIGURATION.md`](docs/API_CONFIGURATION.md)，开发说明见 [`docs/DEVELOPMENT.md`](docs/DEVELOPMENT.md)。

业务数据默认写入 `data/frameflow.db`，可通过 `DATABASE_PATH` 修改位置。当前单机版提供基础版、创作者版和团队版本地套餐切换；正式收费上线时应把套餐切换接口接到支付成功回调，不能直接暴露给普通用户。

## 1. 文档目标

本文档定义一个“用户只需输入一段话，即可自动生成对应视频”的 Agent 平台。平台首期对接字节系视频生成能力（火山方舟 Seedance 系列、即梦开放接口），并通过统一适配层支持未来扩展其他供应商。

本文不是单纯的功能清单，而是产品、交互、工程、商业、合规和上线验收的共同基线。涉及模型名称、价格、配额与商用授权的内容，以签约时供应商最新正式合同和官方控制台为准。

## 2. 事实、假设与待确认项

### 2.1 已确认的公开能力

- 火山方舟提供异步视频生成任务 API，公开文档包含创建、查询、列表、取消或删除任务等能力。
- 官方公开参数会随模型而变化，常见参数包括模型、提示词、参考图、比例、时长等；Seedance 2.0/2.0 fast 的公开资料显示支持 4～15 秒等配置，实际以账户开通能力为准。
- 即梦开放接口存在独立服务地址、签名鉴权和异步任务形态，例如即梦视频 3.0 的相关能力。
- 企业商用需要同时确认 API 使用协议、输出内容权利、素材授权、数据保留、区域与内容合规要求，不能仅凭“API 可调用”推定可无限制商用。

### 2.2 当前假设

- 首发市场以中国大陆为主，界面默认简体中文，架构预留国际化。
- 产品初期提供 Web 端，采用响应式设计；移动 App、小程序、开放 API 延后。
- MVP 聚焦 5～15 秒短视频，长视频采用分镜生成后拼接，不承诺单次模型直接生成长视频。
- 用户输入的一段话会先经过 Agent 进行意图识别、提示词增强、参数选择和合规预检，再调用视频模型。
- 初期采用平台统一供应商账号，企业版可增加 BYOK（客户自带 API Key）与独立资源池。

### 2.3 必须在立项/签约阶段确认

- “Seedance 2.5”是否为供应商正式可用的 API 型号、开通范围、endpoint/model ID、价格、并发与 SLA。截至本文日期，官方公开资料中未检索到足够信息确认该名称。
- 即梦 API 与火山方舟 Seedance 是否存在账号、计费、审核、素材和商用授权上的差异。
- 模型输出是否带显式/隐式水印，平台是否允许展示、下载和商用分发。
- 真人、人脸、品牌商标、未成年人、政治、医疗、金融等内容的额外限制。
- 用户输入和生成素材是否可被供应商用于训练，以及可选的数据不留存机制。

产品中不得写死“Seedance 2.5”。应使用稳定的产品别名（如 `video_standard`、`video_fast`、`video_pro`），由后台模型注册表映射到供应商实际 model ID。

## 3. 产品愿景与边界

### 3.1 产品愿景

让没有提示词、剪辑和模型知识的用户，也能在 3 分钟内从一句自然语言描述得到一条可预览、可迭代、可下载的视频。

### 3.2 核心价值

- 极低门槛：一句话即可生成，不强迫用户理解模型参数。
- 可控结果：Agent 自动补全镜头、主体、动作、光线、镜头语言和负面约束，用户仍可进入高级设置。
- 商业可用：从计费账本、内容审核、版权声明、审计日志到企业权限都纳入首期架构。
- 供应商可替换：同一业务请求可路由到即梦、Seedance 或未来模型，降低供应商锁定风险。
- 可持续运营：可测量获客、激活、生成成功率、复购、毛利与留存。

### 3.3 非目标

MVP 不包含以下能力：

- 专业时间线剪辑器、复杂多轨道后期和 AE 级特效。
- 直播视频实时生成。
- 自研基础视频模型训练。
- 自动发布到全部短视频平台。
- 对所有生成内容作“绝对无侵权”承诺。
- 不经用户确认就自动公开或对外发布作品。

## 4. 目标用户与典型场景

| 用户 | 核心诉求 | 典型任务 | 付费动力 |
|---|---|---|---|
| 个人创作者 | 快速产出、有趣、易上手 | 创意短片、社媒素材 | 生成次数、去水印、高清导出 |
| 电商/营销人员 | 批量、稳定、品牌一致 | 商品卖点、活动广告、信息流素材 | 模板、批量、团队协作、商用保障 |
| MCN/工作室 | 高吞吐、低单位成本 | 多账号日更、A/B 素材 | 并发、API、批量、成本报表 |
| 企业品牌团队 | 权限、合规、审计、资产沉淀 | 品牌宣传、内部传播 | SSO、组织空间、私有素材、SLA |
| 平台运营人员 | 控风险、控成本、促转化 | 审核、套餐、活动、工单 | 内部管理能力 |

## 5. 关键业务指标

### 5.1 北极星指标

每周成功导出的视频用户数（Weekly Successful Video Exporters，WSVE）。

该指标同时要求“生成成功”和“用户认为值得导出”，比单纯调用次数更接近真实价值。

### 5.2 核心指标

- 激活：注册后 24 小时内首次提交率、首次成功生成率、首次导出率。
- 体验：端到端完成时长 P50/P95、排队时长、生成成功率、重试率、用户主动取消率。
- 质量：首版采纳率、再次生成率、提示词编辑率、点赞/踩、投诉率。
- 商业：免费转付费率、ARPPU、额度消耗率、续费率、退款率、单条视频毛利。
- 风控：输入拦截率、输出拦截率、误杀申诉率、侵权投诉率、封禁率。
- 稳定性：API 可用性、供应商错误率、Webhook 延迟、重复扣费率、账实不符率。

## 6. 用户体验总流程

```text
注册/登录
  → 输入一句话
  → Agent 理解意图并生成创作方案
  → 用户直接生成或展开高级设置
  → 费用/额度预估与内容预检
  → 创建异步任务并冻结额度
  → 排队 / 生成 / 审核 / 入库
  → 预览结果
  → 下载、再次生成、做变体或反馈
  → 成功结算；失败/取消按规则解冻或退款
```

### 6.1 理想的一句话示例

> 生成一条 9:16、10 秒的国风香水广告：雨后的江南庭院，一只白瓷香水瓶放在青石台上，镜头缓慢推进，水珠滑落，氛围高级克制，适合小红书。

如果用户只输入“做一个咖啡广告”，Agent 应合理补充默认值，并在结果卡片中透明显示“已为你选择：9:16、8 秒、暖色商业摄影、缓慢推镜”，而不是要求用户填写大量表单。

## 7. Agent 能力设计

### 7.1 Agent 职责

Agent 是业务编排层，不是一个无限自治系统。它只在明确的工具和规则范围内执行：

1. 识别创作目标、平台、时长、比例、风格、主体、动作和镜头语言。
2. 对缺失项应用场景默认值，并标记哪些内容为系统推断。
3. 将长描述整理为结构化 `VideoIntent`。
4. 生成供应商无关的中间提示词 `CanonicalPrompt`。
5. 根据模型能力、价格、队列、用户套餐和合规策略选择模型档位。
6. 进行输入安全预检和版权/肖像风险提示。
7. 估算本次消耗，在用户额度不足时给出明确选项。
8. 调用任务服务，不直接持有供应商密钥。
9. 生成失败时根据错误类型决定自动重试、切换模型或请求用户修改。
10. 记录每一步决策原因、版本和结构化输出，支持审计与复现。

### 7.2 结构化意图

```json
{
  "subject": "白瓷香水瓶",
  "scene": "雨后的江南庭院青石台",
  "action": "水珠滑落，薄雾轻动",
  "camera": "缓慢推进，浅景深",
  "style": "高级、克制、国风商业摄影",
  "audience": "小红书用户",
  "duration_seconds": 10,
  "aspect_ratio": "9:16",
  "quality_tier": "standard",
  "reference_assets": [],
  "negative_constraints": ["不要文字乱码", "不要主体变形"],
  "inferred_fields": ["duration_seconds", "camera"]
}
```

### 7.3 长内容策略

当用户要求生成超过单模型限制的内容时：

- Agent 自动生成脚本和分镜，但必须先让用户确认预计镜头数、成本与总时长。
- 每个镜头独立生成，使用统一角色/风格参考资产维持一致性。
- 后处理服务负责拼接、转场、字幕、旁白、配乐和响度标准化。
- 单镜头失败可局部重试，避免整条视频重新计费。
- MVP 可先仅支持单镜头；多镜头功能作为后续版本，不伪装成已支持。

### 7.4 Agent 失败原则

- 参数错误：不扣费，修正后重试一次。
- 供应商限流/短暂故障：指数退避并加入抖动，达到阈值后切换已授权的兼容模型。
- 内容审核拒绝：不自动改写成规避审核的表达；向用户说明类别并允许合规修改。
- 额度不足：不提交供应商任务。
- 结果质量不满意：属于质量争议，不自动退款；提供有限次数的优惠重做或人工申诉策略。

## 8. 功能需求

### 8.1 访客与账户

- 手机号/邮箱验证码登录，支持第三方登录的后续扩展。
- 用户协议、隐私政策、生成式 AI 服务说明需在注册和首次生成前留痕同意。
- 个人资料、语言、默认主题、默认画幅、通知偏好。
- 账号注销、数据导出、会话撤销、登录设备管理。
- 风险账号支持验证码、人机校验、限频和人工冻结。

### 8.2 创作工作台（P0）

- 页面首屏突出一个自然语言输入框，支持粘贴多行文本。
- 示例提示、随机灵感、历史提示词和最近使用配置。
- 快速选项：比例、时长、清晰度/速度档位、生成数量。
- 高级选项：镜头运动、风格、随机种子（模型支持时）、负面提示、参考图、首尾帧。
- 实时显示预计消耗、预计等待区间和当前套餐余额。
- “优化提示词”可预览修改前后差异，用户可撤销。
- 提交按钮必须防重复点击；同一幂等键只创建一个收费任务。
- 移动端底部固定主操作，桌面端采用左右分栏。

### 8.3 生成任务（P0）

- 支持状态：草稿、预检、待支付/待扣额、排队、已提交、生成中、后处理、审核中、成功、失败、已取消、已过期。
- 展示明确进度阶段，不伪造模型无法提供的精确百分比。
- 支持离开页面后后台继续生成。
- 站内通知为必选，邮件/短信/浏览器通知可配置。
- 在供应商允许时支持取消；取消后的费用按供应商实际计费结果结算。
- 可对失败任务一键重试，并保留父子任务关系。
- 同一项目下支持“做变体”“改提示词再生成”“更换比例”。

### 8.4 作品与资产库（P0）

- 网格/列表视图，按项目、状态、日期、比例、模型和标签筛选。
- 视频预览、封面、提示词、参数、生成时间、消耗和模型档位。
- 下载原文件/压缩版；下载前再次进行权限与过期校验。
- 删除采用软删除和回收站，企业保留策略可配置。
- 生成结果从供应商临时 URL 主动转存到平台对象存储，避免链接过期。
- 对象存储使用私有桶和短期签名 URL，不把永久公开链接作为默认方案。
- 用户可举报、申诉、标记喜欢/不喜欢。

### 8.5 套餐、额度与支付（P0/P1）

- 支持免费体验、月付订阅、年付订阅、按量充值包和企业合同。
- 前台用“点数/额度”简化表达，后台必须保留真实货币成本与供应商用量。
- 订单、支付、退款、发票、优惠券、订阅续费与到期提醒。
- 额度采用账本，不允许只维护一个可被覆盖的余额字段。
- 生成前冻结额度，成功后结算，确定失败后解冻；每次变动均有不可变流水。
- 支付回调验签、幂等处理、对账、掉单补偿和退款审计。
- 套餐权益由配置中心管理，禁止散落在前端或业务代码中。

### 8.6 团队与企业（P1）

- 组织、工作空间、成员邀请、角色与权限。
- 建议角色：Owner、Admin、Creator、Viewer、Billing、Auditor。
- 团队共享额度、成员预算上限、项目空间、品牌模板和素材库。
- 企业 SSO、SCIM、IP 白名单、操作审计、数据保留策略、专属支持。
- BYOK 密钥加密托管，按租户隔离；密钥仅由后端运行时解密。

### 8.7 运营管理后台（P0）

- 用户、组织、套餐、订单、账本、任务、供应商调用和素材管理。
- 内容审核队列、举报/申诉、封禁、敏感策略和人工复核。
- 模型注册表、模型上下线、别名路由、灰度比例、并发和熔断配置。
- 成本看板：供应商成本、收入、毛利、失败损耗、存储和流量费用。
- 活动、优惠券、邀请码、公告、消息模板和 CMS。
- 客服可查看脱敏任务上下文，但默认不可查看企业私有素材原文件。
- 所有高风险后台操作要求二次确认并写入审计日志。

### 8.8 开放平台（P2）

- API Key、签名、IP 白名单、Webhook、用量和速率限制。
- API 与 Web 端复用同一任务、账本和审核链路。
- Webhook 至少一次投递；消费者以 `event_id` 幂等。
- 提供任务创建、查询、取消、资产下载和用量查询接口。

## 9. 主题与视觉设计系统

### 9.1 设计原则

- 美观但不过度装饰，视频内容始终是视觉主角。
- 关键操作在 3 次点击内完成；默认模式极简，高级参数渐进披露。
- 颜色不作为状态的唯一表达方式，兼顾色弱用户。
- 所有主题共享同一套语义令牌和组件行为，不复制多套页面 CSS。
- 桌面、平板、手机均可使用，最小支持宽度 360px。

### 9.2 内置主题

| 主题 | 定位 | 主色建议 | 背景与材质 | 适用人群 |
|---|---|---|---|---|
| 曜石黑 Obsidian | 专业影视感 | 紫蓝/青色 | 深色、轻微玻璃质感 | 创作者、工作室 |
| 云境白 Cloud | 清爽商务 | 靛蓝 | 大留白、低对比阴影 | 企业、日常办公 |
| 东方绛 Oriental | 东方高级感 | 绛红/鎏金点缀 | 米白/墨色、克制纹理 | 国风、品牌营销 |

主题选择支持“跟随系统 / 云境白 / 曜石黑 / 东方绛”，登录用户云端同步，未登录用户写入本地存储。首屏加载前读取主题，避免闪烁。

### 9.4 关键页面

1. 营销首页：价值主张、示例视频、三步流程、适用场景、价格、FAQ、合规说明。
2. 创作工作台：输入区、参数区、预计消耗、生成按钮、最近任务。
3. 任务详情：阶段进度、预览、参数、费用、失败原因、重试/变体/下载。
4. 作品库：筛选、批量管理、项目与素材详情。
5. 套餐与账单：套餐对比、用量趋势、额度流水、订单与发票。
6. 团队空间：成员、角色、共享资产、预算和审计。
7. 管理后台：运营、审核、任务、模型路由、财务与系统健康度。

### 9.5 无障碍与性能

- 文本与背景对比度达到 WCAG 2.2 AA。
- 完整键盘操作、清晰焦点、表单标签和屏幕阅读器语义。
- 尊重 `prefers-reduced-motion`，关闭非必要动画。
- 视频默认静音预览，不在移动网络自动播放大文件。
- 首页 LCP 目标 ≤ 2.5s（P75），创作工作台核心 JS 按需加载。

## 10. 商业模式与单位经济模型

### 10.1 建议套餐

具体价格必须在拿到供应商正式报价后反推，以下仅定义权益结构：

| 套餐 | 目标用户 | 核心权益 |
|---|---|---|
| Free | 新用户 | 少量体验额度、标准队列、有限存储期、带平台标识 |
| Creator | 个人创作者 | 月度额度、高清下载、更长存储、商用凭证说明 |
| Pro | 专业用户/小团队 | 更多额度、快速队列、批量变体、品牌模板、成员席位 |
| Business | 企业 | 组织权限、审计、共享额度、发票、SLA、可选 BYOK |
| Enterprise | 大客户 | 私有部署/专属资源选项、SSO、定制合规与合同报价 |

“商用”只能表示平台在合同范围内允许商业使用，不能替用户保证其提示词、上传素材、人物肖像、音乐或输出一定不侵犯第三方权利。

### 10.2 成本公式

```text
单任务完全成本 = 模型调用成本
              + 提示词/Agent 模型成本
              + 内容审核成本
              + 后处理计算成本
              + 存储成本
              + 下载流量/CDN 成本
              + 支付通道费分摊
              + 失败与赠送额度损耗分摊
              + 客服与基础设施分摊

毛利率 = (确认收入 - 单任务完全成本) / 确认收入
```

计价引擎的输入至少包括供应商、模型、时长、分辨率、生成数量、优先级、附加处理和租户折扣。价格表必须带版本与生效时间，任务创建时固化价格快照。

### 10.3 商业化护栏

- 提交前显示预计扣额；最终扣额不能高于用户确认值，除非用户再次确认。
- 管理后台设置供应商日预算、租户日预算、单用户速率和全局熔断阈值。
- 免费用户需要设备/账号风控，防止批量薅额度。
- 对高失败率模型自动降权，不让补偿成本吞噬毛利。
- 对存量作品设置分层存储和生命周期，删除前通知用户。
- 每日自动完成供应商账单、内部任务和用户账本三方对账。

## 11. 总体技术架构

### 11.1 架构原则

- MVP 采用模块化单体，降低分布式复杂度；耗时任务通过独立 Worker 扩展。
- Web 请求与视频生成解耦，所有供应商调用都经过任务队列。
- 数据库是真实业务状态来源，消息队列负责传递工作，不把队列当数据库。
- 核心状态变更采用事务 + Outbox，避免“数据库成功、消息发送失败”。
- 供应商回调与主动轮询并存；回调优先，轮询兜底。
- 从第一天支持幂等、限流、熔断、重试、审计和成本归集。

### 11.2 逻辑架构

```text
[Web / Mobile Web / Admin]
            |
        [API Gateway]
            |
  +---------+-----------------------------------+
  | Auth | Workspace | Creation | Billing      |
  | Asset| Moderation| Provider | Notification |
  +---------+-----------------------------------+
            |                         |
      [PostgreSQL]              [Redis/Queue]
                                      |
                             [Generation Workers]
                                      |
                         [Provider Adapter Layer]
                         /                    \
              [Volcengine Ark]          [Jimeng API]
                         \                    /
                           [Callback/Poller]
                                  |
                         [Post-process Worker]
                                  |
                         [Private Object Storage]
                                  |
                               [CDN]
```

### 11.3 推荐技术栈

技术栈不是硬性要求，但建议优先选择团队熟悉且生态成熟的组合：

- 前端：Next.js + TypeScript + React + Tailwind CSS/CSS Variables + TanStack Query。
- 后端：当前采用 FastAPI/Python，便于承载 Agent 编排、供应商适配和异步任务接口。
- 数据库：PostgreSQL；缓存与分布式锁：Redis。
- 队列：初期 Redis Streams/BullMQ；规模上升后评估 RabbitMQ/Kafka。
- 对象存储：火山引擎 TOS 或兼容 S3 的私有对象存储；CDN 用鉴权 URL。
- 媒体处理：FFmpeg Worker，使用受限容器运行，不拼接用户输入为 Shell 命令。
- 可观测性：OpenTelemetry + Prometheus/Grafana + 集中日志 + 错误追踪。
- 部署：Docker；初期托管容器/云主机，规模化后 Kubernetes。

不建议 MVP 一开始拆成大量微服务。按领域分模块、按负载拆进程，为未来拆分保留接口即可。

## 13. 任务状态机与可靠性

### 13.1 内部状态

```text
DRAFT
  → PRECHECKING
  → CREDIT_RESERVED
  → QUEUED
  → SUBMITTING
  → GENERATING
  → POST_PROCESSING
  → OUTPUT_MODERATING
  → SUCCEEDED

任意可取消阶段 → CANCELLING → CANCELLED
任意执行阶段   → RETRY_WAIT → QUEUED
不可恢复错误   → FAILED
结果超期       → EXPIRED
```

供应商状态不得直接作为内部状态；由适配层映射，以免供应商字段变化污染业务。

### 13.2 幂等与重试

- 前端每次用户动作生成 `Idempotency-Key`，服务端保存请求指纹和响应。
- 创建供应商任务前先持久化内部任务；供应商请求需关联唯一请求 ID。
- Webhook 按 `provider + external_event_id` 去重。
- 轮询任务使用指数退避、抖动和最大期限，避免固定频率打爆接口。
- 仅对网络失败、429、部分 5xx 等可恢复错误重试；业务拒绝和参数错误不盲目重试。
- 未知提交结果进入 `RECONCILING`/人工对账流程，绝不能直接再次扣费创建。
- 采用租约或可见性超时防止 Worker 崩溃造成任务永久占用。

### 13.3 额度一致性

```text
AVAILABLE → RESERVED → CONSUMED
                    ↘ RELEASED
```

- 冻结、结算和释放均使用数据库事务和唯一业务键。
- 每笔账本流水记录用户、组织、任务、币种/额度类型、数量、前后余额、原因和操作方。
- 账本记录只追加，不物理修改；冲正通过反向流水完成。

## 14. 核心数据模型

建议的核心表：

- `users`：用户、状态、区域、偏好。
- `identities`：手机号、邮箱、第三方身份。
- `organizations`、`memberships`、`roles`：企业与权限。
- `projects`：作品项目与共享范围。
- `assets`：上传素材、生成视频、封面、元数据、版权声明、存储位置。
- `creation_requests`：用户原始输入和结构化意图。
- `generation_tasks`：内部任务、状态、价格快照、父子关系。
- `provider_attempts`：每次供应商提交、外部任务 ID、耗时、错误与成本。
- `model_registry`：模型能力、别名、路由和版本。
- `prompt_versions`：原始提示、标准提示、供应商提示、Agent/策略版本。
- `wallets`、`ledger_entries`、`credit_reservations`：余额、账本与冻结。
- `plans`、`subscriptions`、`orders`、`payments`、`refunds`：商业交易。
- `moderation_cases`：输入/输出审核、原因、证据、申诉。
- `notifications`、`webhook_deliveries`：通知与开放平台回调。
- `audit_logs`：后台、权限、计费与密钥等敏感操作。
- `outbox_events`：可靠事件发布。

所有业务表建议包含 `id`、`created_at`、`updated_at`；多租户表包含 `organization_id`，并在数据库访问层强制租户过滤。

## 16. 安全、隐私、内容与知识产权

### 16.1 安全基线

- 全链路 TLS；密码使用现代密码哈希；会话 Cookie 使用 Secure、HttpOnly、SameSite。
- 供应商/API/支付密钥进入 KMS 或 Secrets Manager，禁止写入仓库、日志和前端。
- 后台最小权限、MFA、短会话、关键操作二次认证。
- 上传文件检查 MIME、魔数、大小、分辨率、病毒；文件名不参与存储路径拼接。
- 私有对象存储、短期签名 URL、防盗链与下载权限校验。
- 防护 SSRF、越权访问、SQL 注入、XSS、CSRF、重放攻击和队列投毒。
- 日志脱敏手机号、邮箱、Token、提示词中的敏感个人信息。
- 依赖漏洞扫描、镜像扫描、SAST/DAST、密钥扫描和定期渗透测试。

### 16.2 内容安全

采用“输入预检 + 供应商审核 + 输出复检 + 举报申诉 + 人工复核”链路，覆盖但不限于：

- 违法违规、暴力血腥、色情、仇恨、极端主义。
- 未成年人不当内容。
- 政治敏感与公共事件误导。
- 真人深度伪造、肖像冒用和未经同意的人脸素材。
- 商标、角色、影视 IP、音乐和其他版权风险。
- 医疗、金融等可能造成实际伤害的误导内容。

对真人参考素材增加权利确认；高风险场景可要求实名、授权书或直接禁用。生成内容按适用法律法规和供应商要求添加 AI 生成标识/元数据。

### 16.3 隐私与数据治理

- 明示收集目的、范围、保存期限、第三方处理者和跨境情况。
- 用户可删除资产和注销账号；法律/财务必须保留的数据与普通内容分离。
- 提示词、参考图和视频建立可配置生命周期；免费套餐默认保存期更短。
- 企业数据默认不用于平台训练；如未来希望用于改进，必须独立、明确、可撤回地征得同意。
- 建立数据分级、访问审批、导出水印、审计和泄露响应流程。

### 16.4 商用前法务清单

- 平台主体资质与适用的生成式 AI、深度合成、算法/备案要求。
- 用户协议、隐私政策、版权政策、可接受使用政策、退款政策。
- 供应商主协议、DPA/数据处理条款、SLA、商用授权和赔偿边界。
- 支付、税务、发票、未成年人、消费者权益和自动续费提示。
- 侵权通知—删除—申诉机制及法务联络渠道。

此处为产品需求，不构成法律意见；上线前必须由目标运营地区的专业律师审核。

## 18. 可观测性与运营告警

### 18.1 全链路标识

每次生成应关联：`request_id`、`trace_id`、`user_id`、`organization_id`、`generation_id`、`provider_attempt_id`、`external_task_id`、`price_version`、`policy_version`。

### 18.2 指标与看板

- API：吞吐、延迟、错误码、认证失败、限流。
- 队列：等待数、最老任务年龄、消费速率、死信数量。
- 供应商：创建成功率、完成成功率、耗时分位、429/5xx、单位成本。
- 账单：冻结未结算年龄、扣费/释放失败、对账差异。
- 存储：转存失败、签名 URL 失败、生命周期删除量。
- 业务：漏斗、留存、付费、毛利、套餐额度使用分布。
- 风控：拦截、申诉、误杀和高风险账号。

### 18.3 告警示例

- 5 分钟供应商创建失败率 > 10%。
- 最老排队任务 > 10 分钟或队列增长持续 15 分钟。
- 任一重复扣费事件立即 P0 告警。
- 冻结额度超过任务终态 30 分钟未结算。
- 对象存储转存失败率 > 2%。
- 当日供应商成本达到预算的 70%/90%/100%。

## 19. 测试策略

### 19.1 自动化测试

- 单元测试：提示词解析、能力校验、价格计算、状态映射、账本规则。
- 契约测试：为每个供应商保存脱敏请求/响应样本，校验适配器兼容性。
- 集成测试：数据库、队列、对象存储、支付回调、Webhook 幂等。
- 端到端测试：注册 → 输入 → 冻结 → 生成 → 转存 → 审核 → 下载 → 结算。
- 故障注入：超时、429、5xx、回调重复/乱序/丢失、Worker 崩溃、存储失败。
- 安全测试：越权、恶意文件、签名伪造、重放、提示注入、敏感信息泄露。
- 视觉回归：三个主题、响应式断点、暗色对比度和主题首屏闪烁。

### 19.2 模型质量评测集

建立可版本化的 100～300 条内部提示集，覆盖人物、动物、产品、国风、写实、动画、镜头运动、文字元素、横竖屏和敏感边界。每次模型或提示词策略升级比较：

- 指令遵循、主体一致性、动作自然度、画面稳定性。
- 参考图一致性、构图、审美、伪影和文字乱码。
- 生成时延、成功率、成本和审核通过率。

模型升级不只看主观画质，必须同时看成本、稳定性与合规指标。

## 20. 发布与环境

### 20.1 环境

- Local：本地 Mock 供应商，禁止调用真实付费接口。
- Dev：共享开发环境，可用低成本/沙箱账号。
- Staging：生产等价配置、隔离账号和支付沙箱。
- Production：最小权限、审批发布、备份与灾备。

各环境数据库、对象存储、密钥、回调地址和供应商账号必须隔离。

### 20.2 发布策略

- 数据库迁移向后兼容，先扩展后收缩。
- 功能开关控制新模型、新主题、支付和企业能力。
- 新模型先内部流量，再 1%/10%/50% 灰度；根据质量与成本自动或人工回滚。
- 发布前自动测试、迁移检查、镜像签名和变更审计。
- 建立供应商故障、支付故障、内容安全事件和数据泄露预案。

## 21. 版本路线图

### Phase 0：技术与商业验证（1～2 周）

- 完成供应商商务沟通、企业认证和 API 权限申请。
- 确认真实模型 ID、参数、QPS、计费、回调、水印和商用条款。
- 用 30～50 条提示词完成画质、时延、成本和审核对比。
- 建立单任务完全成本表，确定是否存在正毛利空间。
- 输出结论：继续、调整定位或更换供应商。

### Phase 1：MVP（4～6 周）

- 登录、创作工作台、一句话解析、文生视频。
- 单一主供应商 + Mock 适配器，异步任务、轮询、结果转存。
- 三套主题、响应式页面、任务详情和作品库。
- 免费额度、冻结/结算账本、基础管理后台。
- 输入/输出审核、基础风控、日志指标和错误告警。

MVP 上线门槛：完整闭环可用、账本零重复、任务不丢失、内容安全可处置，而不是仅“成功调用一次模型”。

### Phase 2：商业 Beta（4～6 周）

- 正式支付、订阅、订单、退款、发票流程。
- 第二供应商/第二模型、智能路由和故障降级。
- 图生视频、首尾帧、变体、通知中心。
- 成本/毛利看板、运营活动、客服与申诉。
- 邀请制开放，验证转化、毛利和支持成本。

### Phase 3：增长与企业版（6～10 周）

- 多镜头 Agent、字幕、配音、配乐和自动后期。
- 组织空间、品牌模板、成员预算、审计与 BYOK。
- 开放 API/Webhook、SSO、企业 SLA。
- 批量任务、渠道模板、A/B 创意和数据分析。

## 22. MVP 验收标准

### 22.1 功能验收

- 用户输入一句中文描述，不进入高级设置也能成功创建视频。
- 提交前可看到预计额度，余额不足不会调用供应商。
- 刷新/关闭页面不影响后台任务，重新登录后可查看进度。
- 同一请求重复提交不会产生两个任务或两次扣费。
- 供应商回调重复、乱序或缺失时，内部状态最终一致。
- 成功结果被转存到平台私有存储，可预览和下载。
- 失败、取消、审核拒绝都按规则正确结算或释放额度。
- 三套主题可切换、可持久化，无明显首屏闪烁。
- 管理员可以定位任务、查看脱敏错误、处理申诉并审计操作。

### 22.2 质量验收

- 预设评测集成功完成率达到项目签字阈值（建议 ≥ 90%，供应商政策拒绝另计）。
- 端到端生成耗时有 P50/P95 基线并在界面如实呈现。
- 核心页面完成移动端和桌面端视觉验收。
- 无 P0/P1 安全漏洞；密钥扫描无泄漏。
- 对账脚本可解释每个任务的用户扣额与供应商成本。
- 隐私、用户协议、生成式 AI 标识和内容处置流程经法务确认。

## 23. 主要风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| Seedance 2.5 名称/权限未确认 | 无法按预想接入 | Phase 0 获取正式文档；使用别名和适配层 |
| 供应商价格或规则变化 | 毛利下降、功能失效 | 价格版本化、日预算、动态路由、合同约束 |
| 高峰限流与排队 | 用户流失 | 配额申请、队列预估、优先级、第二供应商 |
| 输出质量不稳定 | 退款与投诉 | 评测集、提示词策略版本、有限重做、质量反馈 |
| 真人/版权侵权 | 法律与品牌风险 | 授权确认、审核、投诉删除、审计证据 |
| 任务成功但平台未收到结果 | 用户和成本损失 | 回调 + 轮询、对账任务、人工恢复工具 |
| 额度/支付不一致 | 直接财务损失 | 不可变账本、幂等、Outbox、三方对账 |
| 视频存储/流量过高 | 毛利被侵蚀 | 生命周期、分层存储、压缩预览、下载限额 |
| 多主题导致维护成本高 | UI 不一致 | 语义令牌、组件库、视觉回归 |
| Agent 自由度过高 | 结果不可控、难审计 | 结构化输出、工具白名单、版本化、确定性规则兜底 |

## 24. 立项决策门（Go/No-Go）

进入正式开发前，必须回答：

1. 是否拿到至少一个可生产使用的视频 API 账号和正式商用授权？
2. 100 条目标场景测试中，质量与成功率是否达到可销售水平？
3. 加上失败损耗、存储、流量和支付后，目标套餐是否仍有合理毛利？
4. 内容安全、投诉申诉和 AI 标识是否能满足运营地区要求？
5. 供应商故障时，是允许排队、降级，还是暂停接单？产品文案是否一致？
6. 平台能否做到任务不丢、额度不重扣、成本可对账？

任一关键问题无法回答时，应继续技术/商务验证，不应通过页面包装掩盖底层不确定性。

## 25. 视频清晰度与成本控制

创作页的“输出清晰度”可以直接选择 `480p`、`720p` 或 `1080p`。项目采用以下低成本默认组合：

- `720p` + Fast 模型
- `5 秒`
- 关闭同步生成声音

试稿时可选择 `480p` 进一步降低消耗；最终交付时再切换为 `1080p`。由于 Fast 模型不支持 `1080p`，选择 `1080p` 后系统会自动使用标准模型。

界面中的“预计消耗”是平台内部创作额度，不等同于火山引擎账单金额。实际供应商费用取决于任务返回的 token 用量及火山引擎实时价格。

相关实现位置：

- 前端选项与默认值：`public/index.html`、`public/app.js`
- 火山引擎请求参数与模型选择：`backend/providers/volcengine.py`
- 接口字段与后端默认值：`backend/models.py`
